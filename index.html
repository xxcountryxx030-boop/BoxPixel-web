¿Qué es Hydra AI?

Una inteligencia artificial propia, creada desde cero.

Hydra AI es una inteligencia artificial conversacional avanzada, impulsada por el modelo YDR — diseñado, entrenado y construido desde cero por el equipo de Hydra. Es un sistema independiente y autónomo: entiende lo que pedís en lenguaje natural y responde en tu mismo idioma, con calidad profesional en texto, código, imágenes y voz.

Modelos YDR

La familia de modelos que mueve a Hydra.

  • YDR 1.5 — rápido y liviano para charla y tareas cotidianas.
  • YDR 2.0 — más equilibrado, mejor razonamiento.
  • YDR 2.5 — el más capaz: código, proyectos y respuestas complejas. (Por defecto)

Qué puede hacer

Las capacidades principales de Hydra AI.

  • Chat multilingüe — conversa y responde en tu mismo idioma, de forma natural.
  • Programación godly — genera código completo y funcional, sin recortes, con botones de copiar, ejecutar y descargar.
  • Arquitecto de proyectos — pedile un proyecto completo y te arma la estructura profesional (árbol de carpetas), el código de todos los archivos y cómo ejecutarlo. Podés descargar todo en un .zip con las carpetas reales.
  • Prompts profesionales — pedile que te cree o mejore un prompt para cualquier IA y te lo entrega estructurado y listo para copiar.
  • Generación de imágenes — creá imágenes a partir de una descripción.
  • Dictado por voz — hablá y Hydra transcribe lo que decís.
  • Búsqueda web — complementa las respuestas con información de la web.
  • Memoria — Hydra recuerda cosas sobre vos entre chats para personalizar sus respuestas.

Cómo usar tus modelos

Una vez creado, tu modelo se usa en dos lugares: en el chat y desde la Hydra API. Sus funciones (ver imágenes, crear imágenes, redactar prompts, armar proyectos) se aplican según lo que hayas activado.

En el chat

Abrí el selector de modelo arriba del cuadro de mensaje y elegí tu modelo. Charlás con él ahí mismo; se mantiene elegido hasta que cambies a Hydra AI u otro.

En la Hydra API

Pasá el nombre exacto del modelo en model. Reemplaza al system (aunque podés sumar uno). El modelo debe ser tuyo o público.

JSON del body
{
  "model": "Pepe",
  "messages": [
    { "role": "user", "content": "Hola, ¿qué hora es?" }
  ],
  "mode": "balanced"
}

Si el model no existe o no es tuyo ni público, la API responde 404. Sin model, responde Hydra AI por defecto. La documentación completa de la API está en Hydra API → Ver documentación.

Documentación · Hydra API

Endpoint y autenticación

Hacé un POST con tu key en Authorization: Bearer <key>. La respuesta es compatible con clientes OpenAI: el texto llega en choices[0].message.content.

POST https://ftnezbtydnviwduydqsk.supabase.co/functions/v1/hydra-chat

Cuerpo de la petición

El body es un JSON con dos campos:

messages requerido
Array estilo OpenAI. Cada ítem es { "role": "system" | "user" | "assistant", "content": "..." }. Se usan los últimos 8 mensajes del historial (los system no cuentan en ese tope; van aparte).
mode opcional
Controla el largo y el estilo de la respuesta. Por defecto balanced.
model opcional
Nombre exacto de uno de tus modelos personalizados (o de uno público). Ej. { "model": "Pepe" }. Aplica su prompt y funciones. Si lo omitís, responde Hydra AI por defecto. Ver la sección "Modelos personalizados" abajo.
image opcional
Poné "image": true (con un prompt o un mensaje de usuario) para generar una imagen directamente. Devuelve la URL en image_url. Ver la sección "Crear imágenes" abajo.
supergo~80 tokUna frase o palabra.
instant~150 tokUltra conciso (máx. 2 oraciones).
turbo~300 tokInformativo (3-5 oraciones).
balanced~600 tokEstándar, tono natural. Default.
creative~700 tokMetáforas e imaginación.
analytical~800 tokLógica paso a paso.
pro~900 tokDetallado, con razonamiento.
supercreative~900 tokVívido, con humor y storytelling.
hydracode~4096 tokCódigo completo y de alta calidad.
full~1400 tokCompleto, cubre todos los aspectos.
ultral~2200 tokProfundidad enciclopédica.

Si el mensaje es largo (+200 caracteres) el tope sube un poco solo (hasta 4096 tokens).

Dale personalidad (system prompt)

¿Querés que tu bot tenga un rol, tono o reglas propias? Agregá un mensaje con "role": "system" al principio del array messages. Define cómo se comporta y funciona en cualquier plataforma (web, Discord, Telegram, apps, scripts…), igual que en OpenAI/ChatGPT.

JSON del body
{
  "messages": [
    { "role": "system", "content": "Sos Pepe, un asistente pirata. Respondé siempre en verso y con humor." },
    { "role": "user", "content": "Hola, ¿qué hora es?" }
  ],
  "mode": "balanced"
}

El system manda: define la persona, idioma, reglas o formato de respuesta de tu bot. Si no mandás ninguno, Hydra usa su comportamiento por defecto. Podés incluir varios system y se combinan. Va siempre dentro de messages (no como campo suelto).

Ver imágenes (visión)

La API puede ver imágenes. No hay que activar nada aparte: mandá el content del mensaje como un array con una parte text y una (o varias) parte image_url — el mismo formato de visión de OpenAI. Hydra analiza la imagen y responde sobre lo que muestra.

JSON del body
{
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "¿Qué hay en esta imagen?" },
        { "type": "image_url", "image_url": { "url": "https://ejemplo.com/foto.jpg" } }
      ]
    }
  ]
}

La imagen va como URL pública o como base64 ("url": "data:image/jpeg;base64,..."). Podés mandar varias imágenes en el mismo content, y combinarlo con tu system prompt. Se detecta sola: si hay image_url, Hydra la ve.

Crear imágenes (generar imágenes)

Además de ver imágenes, la API puede crearlas. La forma más simple: agregá "image": true al body y mandá la descripción en prompt (o como el último mensaje user). Genera la imagen al toque y devuelve la URL directa en image_url (y la imagen en markdown dentro de choices[0].message.content). Funciona con cualquier API key Max, con o sin model.

JSON del body
{
  "image": true,
  "prompt": "un zorro astronauta flotando sobre la Tierra, muy detallado"
}
Respuesta
{
  "model": "hydra-image",
  "image_url": "https://cdn.../imagen.png",
  "choices": [
    { "message": { "role": "assistant", "content": "![imagen](https://cdn.../imagen.png)" } }
  ]
}

También podés usar "mode": "image". Y de forma natural: Hydra por defecto (y los modelos con la función “Crear imágenes” activada) detectan solos cuando pedís una imagen en el chat (“generá una imagen de…”) y la devuelven incrustada como ![imagen](url), sin ningún campo extra.

Con tu modelo personalizado: 1) en la sección Modelos abrí (o creá) tu modelo y marcá la función “Crear imágenes”; 2) llamá a la API con "model": "TuModelo" y pedile la imagen en lenguaje natural — mantiene su persona y devuelve la imagen incrustada. El campo "image": true también funciona junto a model si querés forzar la generación desde el prompt.

Tu modelo + imagen
{
  "model": "Pepe",
  "messages": [
    { "role": "user", "content": "Dibujame un mapa del tesoro pirata" }
  ]
}

Mostrar las imágenes generadas (en tu web, bot o app)

Generar la imagen y mostrarla son dos cosas distintas: la API te devuelve la imagen como una URL directa lista para usar, pero sos vos quien la pinta en tu página, bot o programa. La URL viene en image_url (forma directa) y también dentro de choices[0].message.content como ![imagen](url) (siempre). Con cualquiera de las dos te alcanza.

Helper: sacar la URL de cualquier respuesta
function hydraImageUrl(resp) {
  if (resp && resp.image_url) return resp.image_url;        // forma directa
  const md = resp?.choices?.[0]?.message?.content || "";     // forma natural (markdown)
  const m = md.match(/!\[[^\]]*\]\(([^)\s]+)\)/);
  return m ? m[1] : null;
}

En una web: poné la URL en el src de un <img>. No hace falta descargar nada — el CDN sirve la imagen directo.

HTML + JS
<img id="salida" alt="imagen generada" style="max-width:100%">
<script>
async function generar(prompt) {
  const res = await fetch("https://ftnezbtydnviwduydqsk.supabase.co/functions/v1/hydra-chat", {
    method: "POST",
    headers: { "Authorization": "Bearer TU_API_KEY", "Content-Type": "application/json" },
    body: JSON.stringify({ image: true, prompt })
  });
  const url = hydraImageUrl(await res.json());
  if (url) document.getElementById("salida").src = url;   // ← acá se ve la imagen
}
generar("un zorro astronauta flotando sobre la Tierra");
</script>

¿Ya renderizás Markdown? Si tu app muestra las respuestas de Hydra con un render de Markdown (como marked), el ![imagen](url) del content se ve como imagen sin hacer nada extra — es como la web de Hydra muestra las imágenes en el chat.

Bot de Discord (discord.js)

Modo Agente (crear archivos y ejecutar comandos)

Beta

Activá la función Modo Agente en un modelo y, al usarlo por la API, el modelo deja de solo “dar el código” y se comporta como un agente autónomo: planea → actúa → verifica → sigue hasta terminar la tarea. Emite marcadores de acciones que tu editor (el Hydra IDE) parsea para crear, editar, borrar y leer archivos y ejecutar comandos reales en el workspace. El texto normal (explicaciones) va aparte; el contenido de cada archivo va completo dentro de su bloque.

Tu IDE detecta estos bloques en choices[0].message.content y los ejecuta. Las rutas son siempre relativas a la raíz del workspace, que persiste entre turnos. El protocolo tiene 13 marcadores: para cambios chicos el modelo usa edición quirúrgica (HYDRA_EDIT, buscar/reemplazar exacto) en vez de reescribir todo; para archivos nuevos o reescrituras grandes usa HYDRA_FILE. También puede agregar al final, mover/renombrar, crear carpetas y listar el árbol con marcadores propios; HYDRA_RUN sigue siendo su herramienta multiuso (instalar dependencias, scaffolding, build, tests, correr la app, git). Al estilo de un agente de codificación moderno también busca antes de editar (HYDRA_GREP por contenido/regex, HYDRA_GLOB por nombre de archivo), auto-verifica sus cambios (HYDRA_VERIFY declara un build/test que el IDE re-corre solo tras cada cambio) y mantiene una lista de tareas viva (HYDRA_PLAN).

Marcadores del protocolo (13)
# Editar un archivo QUIRÚRGICAMENTE — el default para cambios chicos.
# El SEARCH debe coincidir EXACTO (indentación incluida). Podés apilar varios
# pares SEARCH/REPLACE en un mismo bloque; se aplican en orden.
<<<HYDRA_EDIT path="src/app.js">>>
<<<SEARCH>>>
texto viejo EXACTO
<<<REPLACE>>>
texto nuevo
<<<END_HYDRA_EDIT>>>

# Crear un archivo NUEVO o sobrescribir/reescribir COMPLETO (para archivos nuevos o reescrituras grandes)
<<<HYDRA_FILE path="src/index.html">>>
<contenido COMPLETO del archivo>
<<<END_HYDRA_FILE>>>

# Agregar contenido al FINAL de un archivo (lo crea si no existe)
<<<HYDRA_APPEND path="log.txt">>>
<contenido a agregar>
<<<END_HYDRA_APPEND>>>

# Leer un archivo antes de seguir (el IDE devuelve su contenido y el modelo continúa)
<<<HYDRA_READ path="src/app.js">>>

# Listar el árbol de archivos (sin path = raíz; el IDE devuelve el árbol)
<<<HYDRA_LIST path="src">>>

# Buscar en el CONTENIDO de los archivos (regex; path opcional = subcarpeta).
# Read-only: el IDE devuelve los matches (archivo:línea) y el modelo sigue. Buscá antes de editar.
<<<HYDRA_GREP query="function\s+parseUser" path="src">>>

# Buscar ARCHIVOS por patrón de nombre (glob: ** = cualquier profundidad, * = un segmento).
# Read-only: el IDE devuelve la lista de rutas que matchean.
<<<HYDRA_GLOB pattern="**/*.test.js">>>

# Mover o renombrar (crea las carpetas destino que falten)
<<<HYDRA_MOVE from="viejo/a.js" to="nuevo/b.js">>>

# Crear una carpeta vacía
<<<HYDRA_MKDIR path="src/utils">>>

# Borrar un archivo o carpeta
<<<HYDRA_DELETE path="viejo.txt">>>

# Ejecutar un comando de terminal (uno por bloque, en orden).
# npm/pip install, npx create-…, build, tests, correr la app, git, etc.
<<<HYDRA_RUN>>>
npm install
<<<END_HYDRA_RUN>>>

# Declarar el comando de VERIFICACIÓN una vez (build/test/lint). El IDE lo re-corre
# SOLO tras cada cambio y te devuelve los errores para que los arregles y re-verifique.
<<<HYDRA_VERIFY>>>
npm test
<<<END_HYDRA_VERIFY>>>

# Lista de tareas VIVA para trabajos multi-paso. Se pinta como card y se actualiza
# cada turno: [ ] pendiente, [~] en curso, [x] hecho. Re-emitir el bloque actualiza la misma card.
<<<HYDRA_PLAN>>>
[x] Explorar el código y ubicar el bug
[~] Escribir el fix
[ ] Correr los tests
<<<END_HYDRA_PLAN>>>

Cómo lo integrás en tu IDE (spec del parser): 1) mandás el pedido del usuario a hydra-chat con model = tu modelo con Modo Agente; 2) en la respuesta, buscás estos marcadores con regex y aplicás cada acción en orden. Reglas por marcador: HYDRA_EDIT reemplaza cada SEARCH por su REPLACE en el archivo (match EXACTO, carácter por carácter; podés tener varios pares por bloque, en orden); si un SEARCH no aparece, devolvé un error para que el modelo relea y reintente. HYDRA_FILE escribe/sobrescribe el archivo completo; HYDRA_APPEND agrega al final (crea si falta); HYDRA_MOVE mueve/renombra creando las carpetas destino; HYDRA_MKDIR crea carpeta vacía; HYDRA_DELETE borra; HYDRA_READ y HYDRA_LIST son de lectura (devolvés contenido / árbol); HYDRA_RUN corre un comando. Los 4 marcadores estilo agente moderno: HYDRA_GREP y HYDRA_GLOB son de lectura (auto-cerrados, sin END) — buscás por contenido (regex sobre cada línea, devolvés archivo:línea) o por nombre (glob → regex, devolvés rutas) y mandás los resultados de vuelta al modelo (mismo round-trip que READ/LIST); HYDRA_VERIFY no ejecuta al vuelo: guardás su comando y lo re-corrés automáticamente tras cada turno con mutaciones (si no hay comando, un fallback tipo node --check por archivo .js editado), devolviendo la salida — con un aviso claro si el exit ≠ 0 — para que el modelo se auto-corrija; HYDRA_PLAN es de lectura y actualiza una card de tareas reusada (parseás cada línea: [ ] pendiente, [~]/[-]/[>] en curso, [x] hecho). HYDRA_GREP, HYDRA_GLOB y HYDRA_PLAN no mutan el disco, así que no pasan por el gate de permisos. Escribir en a/b/c.js crea las carpetas que falten; 3) clave para el modo autónomo: después de aplicar las acciones, devolvé la salida de HYDRA_RUN, el contenido de HYDRA_READ, el árbol de HYDRA_LIST, los matches de HYDRA_GREP/HYDRA_GLOB, la salida de la auto-verificación y cualquier error de HYDRA_EDIT como un mensaje nuevo (role:"user") — así el agente ve el resultado, corrige y sigue solo hasta terminar (el loop del Hydra IDE tolera hasta ~25 turnos autónomos). La función Generador de Código es la versión “solo texto”: devuelve el código completo con la ruta de cada archivo, sin ejecutar nada (ideal si no querés que toque el disco).

¿Dónde corre el Modo Agente? El modelo solo emite los marcadores; quien los aplica de verdad es tu integración. Son dos capas: (1) el parser (detectar los marcadores con regex — igual en todos lados) y (2) el ejecutor (tocar archivos y correr comandos — cambia según tu plataforma). Conviene escribir el parser contra una interfaz io y darle una implementación distinta por plataforma.

1) Parser → interfaz io (común a web y programas)
// Aplica cada acción parseada contra un objeto `io` (lo implementás por plataforma).
async function applyAction(a, io) {
  switch (a.type) {
    case "FILE":   return io.write(a.path, a.content);      // crear/sobrescribir completo
    case "APPEND": return io.append(a.path, a.content);     // agregar al final (crea si falta)
    case "EDIT":   return io.edit(a.path, a.pairs);         // pairs: [{search, replace}, ...]
    case "MOVE":   return io.move(a.from, a.to);            // mover/renombrar
    case "MKDIR":  return io.mkdir(a.path);                 // carpeta vacía
    case "DELETE": return io.remove(a.path);                // borrar
    case "READ":   return io.read(a.path);                  // devolvés el contenido al modelo
    case "LIST":   return io.list(a.path);                  // devolvés el árbol al modelo
    case "RUN":    return io.run(a.command);                // devolvés stdout/stderr al modelo
  }
}
// EDIT: por cada par, si `search` no aparece EXACTO, tirá error y devolvéselo al modelo
// (así relee con HYDRA_READ y reintenta, o reescribe el archivo con HYDRA_FILE).
2a) io en WEB (IDE en el navegador — solo front)
// Archivos: un árbol en memoria (o la File System Access API para disco real).
const files = {}; // { "src/app.js": "..." }
const webIO = {
  write:  (p, c) => { files[p] = c; },
  append: (p, c) => { files[p] = (files[p] || "") + c; },
  read:   (p) => files[p] ?? null,
  move:   (from, to) => { files[to] = files[from]; delete files[from]; },
  mkdir:  ()  => {},                    // no hace falta: la ruta ya lleva la carpeta
  remove: (p) => { delete files[p]; },
  list:   (dir = "") => Object.keys(files).filter(p => p.startsWith(dir)),
  edit:   (p, pairs) => {
    let t = files[p];
    for (const { search, replace } of pairs) {
      if (!t.includes(search)) throw new Error("SEARCH no encontrado en " + p);
      t = t.replace(search, replace);
    }
    files[p] = t;
  },
  // ⚠️ RUN en el navegador NO tiene terminal real:
  //  · Web (HTML/CSS/JS): renderizá los archivos en un <iframe srcdoc> (preview).
  //  · Node/JS: usá WebContainers (StackBlitz) — corre JS en el navegador, NADA más.
  //  · Cualquier otro lenguaje (Python/Rust/…): mandá el comando a un backend tuyo.
  run:    (cmd) => ejecutarEnIframeOWebContainerOBackend(cmd),
};
2b) io en PROGRAMAS (escritorio Electron / o con backend Node)
// Filesystem y terminal REALES → cualquier lenguaje instalado en la máquina.
import fs from "node:fs/promises";
import { dirname } from "node:path";
import { exec } from "node:child_process";
const root = "/ruta/al/workspace";
const nodeIO = {
  write:  async (p, c) => { await fs.mkdir(dirname(p), { recursive: true }); await fs.writeFile(p, c); },
  append: (p, c) => fs.appendFile(p, c),
  read:   (p) => fs.readFile(p, "utf8"),
  move:   async (from, to) => { await fs.mkdir(dirname(to), { recursive: true }); await fs.rename(from, to); },
  mkdir:  (p) => fs.mkdir(p, { recursive: true }),
  remove: (p) => fs.rm(p, { recursive: true, force: true }),
  list:   (dir = ".") => fs.readdir(dir, { recursive: true }),
  edit:   async (p, pairs) => {
    let t = await fs.readFile(p, "utf8");
    for (const { search, replace } of pairs) {
      if (!t.includes(search)) throw new Error("SEARCH no encontrado en " + p);
      t = t.replace(search, replace);
    }
    await fs.writeFile(p, t);
  },
  // Terminal real: corre python, cargo, go, dotnet, npm… lo que haya instalado.
  run:    (cmd) => new Promise(res => exec(cmd, { cwd: root }, (_e, so, se) => res((so || "") + (se || "")))),
};

Resumen por plataforma. En la WEB (front puro): los marcadores de archivos (FILE/EDIT/APPEND/MOVE/MKDIR/DELETE/READ/LIST) y los de búsqueda/plan (GREP/GLOB/PLAN) funcionan perfecto con un árbol en memoria o la File System Access API; pero HYDRA_RUN y la auto-verificación de HYDRA_VERIFY no corren programas arbitrarios — solo tenés preview de HTML/CSS/JS en un iframe, o Node/JS vía WebContainers (o node --check de sintaxis), o mandás el comando a un backend. En PROGRAMAS (app de escritorio con Electron, o un IDE con backend Node): conectás io a fs y child_process y ahí funciona TODO, en cualquier lenguaje (Python, Rust, Go, Java, C#…), porque hay filesystem y terminal reales — el Hydra IDE lo implementa así, re-corriendo HYDRA_VERIFY solo tras cada cambio. En ambos casos, tras aplicar las acciones devolvés al modelo (como mensaje role:"user") la salida de RUN, el contenido de READ, el árbol de LIST, los matches de GREP/GLOB, el resultado de la verificación y los errores de EDIT, y el agente sigue solo.

Si a veces “muestra el código pero no crea nada” (importante)

El modelo casi siempre emite los marcadores, pero de vez en cuando responde con el código en un bloque ``` normal y ningún marcador HYDRA_*. Si tu integración solo aplica marcadores, en esos casos no se crea ni un archivo y parece que “falla”. No es que el marcador esté mal parseado — es que no vino ninguno. La solución es auto-recuperarse: detectá ese caso y pedile UNA vez que reenvíe con marcadores.

Auto-reintento cuando la respuesta no trae marcadores
// Tras recibir la respuesta del modelo:
const actions = parseHydraActions(full);   // tu parser de los 13 marcadores

if (actions.length === 0) {
  const traeCodigo = /```|<!DOCTYPE|<html|import\s|function\s|class\s|def\s/i.test(full);
  // ¿Escribió código pero SIN ningún marcador? → pedí que lo reenvíe como acciones.
  if (traeCodigo && !yaReintente) {
    messages.push({ role: "assistant", content: full });
    messages.push({ role: "user", content:
      "ALTO: mostraste el código como texto en markdown y eso NO crea archivos. " +
      "Reenviá la MISMA solución usando los marcadores, con el contenido COMPLETO. Ejemplo:\n" +
      "<<<HYDRA_FILE path=\"index.html\">>>\n…contenido completo…\n<<<END_HYDRA_FILE>>>\n" +
      "Usá <<<HYDRA_EDIT>>> para cambios chicos y <<<HYDRA_RUN>>> para comandos. " +
      "No expliques de nuevo ni pegues el código como texto: emití SOLO los marcadores." });
    yaReintente = true;              // reintentá UNA sola vez (no en bucle)
    return await otroTurno(messages); // volvés a llamar a hydra-chat con estos mensajes
  }
  // Si tras el reintento SIGUE sin marcadores, avisá al usuario (no te tragues el código
  // en silencio) y revisá que el modelo tenga la función "Modo Agente" ACTIVADA.
}

Con ese reintento, el caso raro se corrige solo y el usuario ni se entera. Si aun tras reintentar nunca aparecen marcadores, el problema no es tu parser: es que ese modelo no tiene activada la función “Modo Agente” (entonces la API no le manda el protocolo). Activala en la sección Modelos del modelo que estés usando.

Errores

Cada error llega como JSON { "error": "..." } con su código HTTP:

  • 400JSON inválido (Invalid JSON body) o falta el array messages ('messages' array required).
  • 401Falta el header Authorization (Missing Authorization header) o la API key es inválida (Invalid Hydra API key).
  • 403La API es exclusiva del plan Hydra Max. Conseguí Hydra Max para usar tus keys.
  • 404El model pedido no existe o no es tuyo ni público. Revisá el nombre exacto.
  • 405Método no permitido: la API solo acepta POST.
  • 500Error interno del servidor. Reintentá con backoff.
  • 503Hydra AI está saturado o en mantenimiento. Reintentá en unos segundos con backoff exponencial.

Regla general: si el status es 2xx, leé choices[0].message.content; si no, leé el campo error del JSON y reintentá solo en 500/503. Si mandás demasiados mensajes muy rápido o repetidos, la API puede frenarte unos segundos (rate-limit).
